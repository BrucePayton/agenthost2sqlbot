# 订阅配置回读与失败恢复修复

针对 session-6fa0b280：组件候选已经找到，创建草稿的返回值因按钮 width 校验失败，读取也失败，随后错误切换到报价数据源，最终耗时约 8 分 44 秒且未完成配置。

后续两条真实会话暴露了持续响应被 60 秒硬截止误杀的问题。超时语义、后续思考默认值和业务提示已按 [持续响应误超时修复](2026-09-13-subscription-response-timeout.md) 调整；下文保留本轮最初实现记录。

## 实现

- 修复 canonical contract 中 8 处按钮/按钮组输出宽度的重叠 oneOf。原生 `default`、`fill`、数值和像素字符串都能回读；写入端仍使用原有枚举、数值下限和像素格式约束。两端生成文件和 Host embed 已重建。
- 公共配置投影逐项通过正式输出 schema 校验。无法表达的操作不作为可重放配置返回，在 `configuration.unresolved` 标出 `READBACK_SCHEMA_INVALID`、操作及字段路径；原生 Store、查询和输出引用保留。诊断优先返回，避免被普通截断提示挤掉。
- 允许写入不受影响的配置项；不能整体覆盖无法完整回读的项。review 对此返回未完成和具体错误，不继续取数或调用保存校验；save 在持久化和确认前阻止。用户在原生表单修复后，重新读当前 revision 即可继续。
- Router 为订阅的输出校验失败返回 `OUTPUT_SCHEMA_INVALID`、`operationMayHaveApplied` 和 `get_context` 恢复动作，区分实际操作与回读结果。原有持久化结果未知处理保持独立。
- Host 保留 `read_required / partial / blocked` 恢复状态，普通候选搜索成功不会清除它。恢复期间阻止重复 start、替代数据集搜索和来源绑定；读取也失败后阻止反复读取。合法草稿回执或新用户回合可重新建立状态。
- 失败阶段关闭思考，成功搜索进入 discovery 阶段并使用回执预算。订阅模型单段处理默认限制为 60 秒，可用 `APP_SUBSCRIPTION_MODEL_STEP_TIMEOUT_SECONDS` 调整；连续思考/正文流不会延长时限。实际工具执行不计入该时限，继续使用工具自身的超时机制。
- 聊天正文新增可信订阅进度：开始核对、实际写入的配置项、创建草稿、检查和具体恢复状态。独立消息不覆盖模型正文，刷新后保留；不靠折叠的“已工作”区域展示。
- Skill 增加同名来源澄清、来源证据、技术错误恢复规则。名称相似、检索排名或日期字段必填不能证明组件来源，不得用报价日期替代成交日期。

恢复门禁针对技术故障；正常场景新增查询和业务歧义仍由需求理解与 Skill 控制。这里没有修改新旧数据 MCP 服务，也没有实现或宣称完整的七步 Tab 自动跟随流程。
