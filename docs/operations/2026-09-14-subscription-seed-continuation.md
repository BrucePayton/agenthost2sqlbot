# 订阅配置来源继承与接续修复

## 问题与改动

会话 `1984b386` 已成功导入图表并填写每日10:00，原生 start_draft 回执耗时499ms。后续约180.7秒没有新的配置工具或正文输出，触发 SUBSCRIPTION_DECISION_LIMIT；不是已发起写入被前端拒绝。

本次修改限定于现有订阅流程：

- 明确原生种子是可信起点，用户明确的滚动日期要求可以调整可编辑的默认固定日期；来源、指标口径、其他筛选/参数、独立查询和人工修改仍受保护。
- 完整当前查询已存在所需比较时复用，确认缺少时 merge 添加；确实读取不全时才定向补证。metadataReady=false 不否定已返回的有效引用，当前草稿缺少比较不等于源图表从未配置比较。
- 原生 comparisonCapabilities 说明原值日期筛选与比较评估期的分工；操作参考明确 filters 是整组替换，修改日期时必须保留其他筛选，并清除不再使用的固定日期值。
- 日期或比较输出未落实时继续 datasets。已有独立确定项可以先写，再使用真实新 outputRef 配置条件和正文；不等待所有步骤拼成一批，不机械增加七次模型往返。
- Host 区分执行时间与发送方式的完成文案；无显式 presentation 时，仪表盘检索复用已宣布的数据/内容阶段，预警图表检索展示实际资源类型。
- 主 Skill 压回原有5200字节预算，操作细节保留在参考文件；保持先回显理解、正文实时进度、原生配置可查看及人工预览保存的边界。

工具契约描述由 Host 源同步生成两端文件，并重建 Host embed bundle。没有修改数据查询引擎、自动预览/保存权限或部署目标环境。

合法Host请求使用本机既有Claude连接配置进行了一次真实运行，该连接尚未证实与失败会话部署环境相同。首轮62.195秒后返回 `SUBSCRIPTION_NO_PROGRESS`，含准备阶段总计64.445秒；前端工具0次、runtime工具0次、助手正文为空。未取得模型有效输出，随后停止，没有换模型、追加提示或反复重试。此为首次模型响应前的阻塞，不能与原会话收到种子后180秒的决策循环等同，也不能从这次Host错误直接推定HTTP502。

## 参数链路核验

2026-09-14 在本机核验 `claude-agent-sdk 0.2.128` 与其 bundled `Claude Code 2.1.220`。这说明本机受检版本的行为，不能代替目标服务实际版本核对。

使用真实 SDK/CLI、隔离的临时配置目录、虚构密钥与仅监听回环地址的 HTTP 接收器。接收器返回合成消息，仅记录请求参数元数据，不访问真实模型或业务服务。模型参数均为 `deepseek-v4-pro-0813`，effort 均实际序列化为 `output_config.effort=low`。

| SDK 设置 | 会话方式 | 实际 HTTP 请求中的 thinking |
| --- | --- | --- |
| enabled，budget_tokens=2048 | 新会话 | `{"type":"adaptive"}` |
| disabled | 恢复上述会话 | 无 thinking 字段 |
| disabled | 新会话 | 无 thinking 字段 |
| disabled，加受控 EXTRA_BODY | 恢复会话 | `{"type":"disabled"}` |

SDK 的参数构造器同时传递 `--resume=<id>` 与 `--thinking disabled`，恢复分支没有丢失该选项。CLI 将 disabled 转换为省略 HTTP 请求中的 thinking；因此不能仅凭 Host 的 `runtime.config.thinking` 断言上游已禁用思考。

本机 CLI 已有 `CLAUDE_CODE_EXTRA_BODY` JSON 支持。通过既有 `ClaudeAgentOptions.env` 提供 `{"thinking":{"type":"disabled"}}`，本地 capture 证实能显式传到恢复会话请求。此为已验证的传递途径，尚未作为生产默认设置；没有新增代理、修改 SDK 或全局配置。

真实网关对照使用已授权的既有 Claude 配置及 Bearer 身份，发送两条相同的无业务数据短提示，分别省略 thinking 和显式 disabled，均使用 low、max_tokens=128，并限制请求等待时间。两组均返回 **HTTP 502、空响应体**，未获得模型输出。因此尚不能判断真实网关是否接受并执行显式禁用，也不能据此认定网关的默认思考行为。记录中不包含网关地址、凭证或模型正文。

本轮保留 180 秒订阅决策上限，不增加自动重试。Host 增加仅元数据的 `THINKING_CONFIG_MISMATCH` 与 `THINKING_DISPLAY_TRUNCATED` 诊断，并在超时中断时记录展示字符数、实际观察字符数与中断标志，避免把 16,000 字符的展示截断误判为流断开。
