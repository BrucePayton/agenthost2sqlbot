# 订阅 Agent 增量配置修复与验收（2026-09-15）

本轮保留现有 configurationIntent、执行器、原生编辑器和正文进度链路。原生 Store 继续持有唯一可写配置，Host 记录需求、已核验证据和实际回执。

## 已实施流程

1. 所有场景先回显具体理解。受理入口接收完整资源名称和确定项，待查字段的业务要求放入 pendingRequirements；只有业务歧义放入 unresolved。支持新版意图能力的配置搜索和写入，在受理前会被执行边界拦截；旧工具目录保持兼容。
2. taskAction 区分新建、继续、修改，targetTaskId 与当前原生任务核对。无关活动草稿不被新需求覆盖。当前原生只有一份活动草稿，遇到真实冲突仍由用户处理旧稿。
3. 时间、发送方式和已知标题/名称尽早写入；用户指定标题与规则名称分别保留。程序生成的名称只在真实重名校验后有界添加后缀。普通整体数据表在要求已明确时自动补齐整体推送；逐条、分组、动态收件人和未决粒度不套用该默认值。
4. 监测指标使用 alert_widget；消息图表/AI 使用 widget；截图和跳转使用 dashboard。空间完整分页后再判定唯一性，打开历史页候选前重读目标页，避免使用过期引用。
5. 预警可先创建空白草稿并填时间，再用 apply_draft.import_widget_source 导入指标。导入复用原生转换，保持同一 taskId；保留时间、接收人和独立内容，继承查询、过滤、参数和策略。已有查询、手改冲突、锁定、晚到回执或账号变化都不能被覆盖。
6. sourceBinding、contentBindings 返回真实来源和内容类型；同一可信对象的目录引用与回读引用复用。删除或替换来源查询后，不再声称来源仍绑定。压缩上下文保留业务含义，已执行需求用于核对而不重复执行。
7. 程序和模型的可信回执统一更新事实。程序待执行动作另按 origin、调用 ID、参数、任务和需求版本核对。模型修复不冒充程序回执；无关或旧回执不能消费新动作。已知 A/B 答案可以直接接续，其余修改只交模型解释增量。
8. 完成校验同时核对业务要求、当前任务和版本、实际配置、待执行动作及原生校验。标题补齐不代表数据需求完成；原生表单 ready 也不能掩盖缺失 AI、条件或未绑定要求。正文首次回执独立核对七类内容、顺序、标题、文本、链接、变量及格式，条件核对实际输出身份和阈值；用户明确修改某项后，只替代对应旧要求，完成判断与模型上下文同步。
9. 配置开始和真实成功继续显示在对话正文，并跟随原生步骤。最终只依据真实配置总结，交接至“命名并保存”，由用户点击“发送预览”、检查后保存。

验收提供者取自现有 Claude 客户端配置。本地 Host 默认地址与之不同，且没有对应 API key；本次结果不能用于判定实际部署环境的模型服务状态。
