# 订阅 Agent 统一配置与找数流程

本次改动覆盖 Host（`claude_workspace_mvp`）和数巢原生配置页面（`davinci/webapp`）。不调用发送预览、保存、启用或发送消息。

## 执行与职责

1. 模型先在对话正文回显理解，提交结构化需求。明确的时间、静态文案和固定接收人可以先配置；找数据不阻塞与其无关的配置。
2. 新任务统一提交原生 `configurationIntent.operations`。程序继续处理操作依赖、临时引用、必填默认项、原生回执及完成判断。`dataBindings` 仅用于已有任务兼容，不再向模型推荐两套配置入口。
3. 每次写入前后沿用现有正文进度与原生页面联动。只有原生成功回执才能显示已完成；用户手动切页后沿用已有页面控制规则。
4. 模型判断业务口径，程序保留已经确认的来源和事实。业务歧义可以提交带精确候选引用的选项，程序展示并记录同一套选项顺序，处理 A/B 等回答后直接继续。
5. 最终以实际配置回读检查完成状态并总结，交给用户在“命名并保存”页面点击“发送预览”，检查数据及消息效果后手动保存。

## 数据查找

- `dataset` 保存指定数据集名称或已核验引用。`fieldRequirements` 汇总查询、筛选、条件、分组、动态接收人、内容及下载所需字段；这些信息只用于发现与证据核验，不是第二份可编辑查询配置。
- 固定内容通知不强制找数据；仪表盘内容按内容资源查找；指标预警使用 `alert_widget` 及其原生查询种子；已指定或选定的数据集保持锁定，变更来源必须显式声明 `changedSelections`。
- 原生字段搜索按请求上限分批执行，复用查询、输出和已核验候选。目录回执保留字段覆盖范围；带过滤的局部搜索不能据此认定字段不存在。
- 字段证据区分精确匹配、同名歧义、角色待核验、已知缺失及尚未查证。名称匹配本身不等于聚合、粒度、枚举或人员映射口径已确认。
- 证据按空间和页面实例隔离，同一任务切换配置页签不丢失已查目录证据。请求返回时校验需求版本，过期或已挂起请求不能覆盖当前事实。
- 目录检索仍受现有每轮调用预算约束；缓存最多保留 6 个数据集、每个 200 个字段，不把截断结果当作完整目录。

## 回执与错误

- 原生字段身份统一处理数字/字符串标识和缺省维度类型，避免表单规范化使同一日期字段变成新字段；来源、角色确实不同时仍保持区分。
- 目录查询绑定成功时，原生页面返回按查询隔离的 `referenceMappings`，记录本次实际发生的目录引用到页面引用转换。该回执由两端程序自动生成和消费，模型继续只填写业务配置。Host 据此核验内容和下载字段，不通过名称或列位置猜测；正文、标题和 URL 不参与引用替换。
- 已绑定字段优先使用当前页面的真实引用，目录证据单独保留，避免两个引用表示造成虚假的业务歧义。字段搜索只有连续分页读取完整后才能用于免查，第一页精确匹配仍不能忽略后页候选。
- 兼容旧绑定时，优先使用当前查询字段和真实输出字段核验。仅缺少字段证据时做一次必要回读，不把一次引用缺失扩散成多项业务要求未满足。
- 原生失败返回原始操作索引、操作名、字段路径及是否提交，程序保留失败信息，只在相关输入改变后解除阻塞。
- 长期生效不能同时带起止日期，范围生效必须带完整日期边界；契约与原生执行共同校验。
- “空间全体成员”目前仍不是原生接收人能力。需求会保留并明确报告，不会被忽略或替换成正文中的 `@所有人`。

## 验证边界

- 两端契约由同一 JSON 源生成，工具定义保持在 Host 32 KiB 上限内。内部定义名称压缩不改变展开后的结构和校验规则。
- 后端单元测试、原生页面测试、真实 ASGI 工具注册以及跨 Origin iframe 检查分别验证；浏览器配置测试使用真实 controller、store、binder 和 readback，资源及外部服务使用固定样本，不访问生产数据。
- 完整 `check:agent-startup` 不能标为通过：最后一轮前端 259/260 项通过，仪表盘 regroup 用例返回 `LAYOUT_MEASUREMENT_TIMEOUT`；随后单独重跑该用例两个分支均通过。此前一次该阶段 260 项全过，但浏览器阶段受沙箱阻止；单独获许可后的浏览器检查全部通过。首轮另外两个布局失败也在修改前 HEAD 上复现。本次没有修改布局或放宽断言，保留这些测试波动记录。
- 当前环境缺少模型运行所需的 API 凭据，真实模型端到端测试未执行；不能据单元测试或浏览器回归宣称实际模型耗时已降低。
