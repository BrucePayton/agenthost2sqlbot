# 订阅 Agent 原生工具流程

2026-09-17：模型直接编排现有五个 space.message_rule 业务工具，撤出整条流程的统一入口、业务计划编译及程序续跑。原生 Store 是唯一可写配置；页面回读是配置事实。此文描述本次代码目标，实际测试及未覆盖项见 [验收记录](subscription-native-tools-validation.md)。

## 分工

| 层 | 职责 | 不承担 |
| --- | --- | --- |
| 模型与 Skill | 回显完整需求、确定场景/依赖、业务口径判断、选择工具、处理真实歧义、对照回读总结 | 不编造引用，不维护另一份执行协议 |
| 五个原生工具 | 读取、搜索、创建、批量修改、检查；工具内校验、精确引用转换、默认标题名称、原子性和版本控制 | 不统包需求理解或猜业务口径 |
| 原生页面与 Store | 当前配置、手工编辑、锁、导航、结构校验、用户预览保存 | 不接受过期修改覆盖人工编辑 |
| Host | SDK/前端传输、账本、真实回执恢复、事实检查点、正文进度、通用权限与错误保护 | 不自动编译业务计划，不替模型宣布业务完成 |

模型可用 get_context、search_options、start_draft、apply_draft、review_draft。历史 save_draft 契约仍被保留，但配置 Agent 不暴露也不执行。start/apply 可一批完成多个确定动作；同批 queryKey/outputKey 是本地引用，跨批使用真实 queryRef/outputRef，并非第二套配置表达。

## 共同执行流程

1. 正文回显理解；所有场景都核实个人/空间归属和当前配置对象。
2. 明确的时间、发送方式、固定内容先配置并展示；粗略理解全需求的依赖后再定向找资源，不先等全部引用。
3. 已有来源和确认引用直接沿用；指定来源定向找字段。未知来源通过现有目录找业务证据，已有目录证据可精确绑定。字段准备一次考虑时间、指标、条件、分组、员工及内容。
4. 查询绑定成功后，用实际输出或同批别名设置依赖项；原子成批执行。真实业务歧义提问，技术错误局部修正。
5. 以最新回读对照原需求及补答；最后写入 finish=true（无写入时 review），通过结构校验后给实际业务总结并交接用户预览/保存。

四条主路径是固定内容通知、仪表盘内容订阅、定时数据推送、条件预警。仪表盘截图/AI/跳转复用同一父对象，监测组件用 alert_widget；动态员工、条件、表格和下载共用一致的查询及卡片范围。所有七类内容组件均使用统一 components 表达；title 单改与 patch_content 保留未涉及内容。

## 确定性边界

首次创建或原生快捷入口首次配置缺标题/名称时，工具补齐默认值；明确输入和模板内容优先，后续人工清空不自动修回。互斥字段从正式 schema 到工具实现严格校验；不浅合并旧新操作。all 的 push-mode 回读无 queryRef、成功 no-op 的 revision 不增长均属合法原生行为。

条件、正文变量和数据表使用当前查询的实际 outputRef，原值和同环比保持不同身份；新增比较 merge 保留原值。多个查询可用同一数据集，不按源去重。

## 进度与续会话

派发前显示正文“正在…”，成功回执显示“已配置…”，页面实际填写同步可查。快且关联的动作合批，不为播报新增模型轮次；失败与人工接管不报成功。finish 的程序通知只说明结构检查通过，最终业务总结由模型根据真实回读生成。

subscription.task 只保留原需求、补答、确认事实、候选来源、原生 taskId/revision 和实际只读回读。当前 revision 超前时旧回读不再作为当前事实。保留真实待消费 SDK 工具回执，不生成伪造结果；过期回执不能推进新配置。用户新要求以最近指令为准，保留无关成功配置。

旧会话可能冻结旧 Skill；识别后返回明确升级提示，保留当前页面和真实回执，不继续执行旧计划。仓库 Skill 是本地 bootstrap 内容，代码修改不等于发布托管 Skill 或更新已有冻结会话；部署验收须检查新会话实际生效的 Skill 版本。

## 验收与边界

验证正式契约、两端生成物、Host embed、原生 Store/Bridge 输入输出、权限/手改/no-op/多查询/比较/动态员工、正文进度及四类自然语言场景。并发测试使用独立进程、数据库和浏览器，不共享全局模型环境变量。

真实自然语言测时分开记录首个有效正文、编辑器打开、工具执行及最终完成，测试数据 fixture 与生产资源/数据明确区分。未实际运行的数据预览、保存、线上 Skill 发布及生产 UAT 不计为通过。本次不改变模型选择，不把简化架构本身当作性能改善证据。
