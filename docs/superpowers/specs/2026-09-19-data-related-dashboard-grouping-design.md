# Data-related Dashboard Grouping Design

## Goal

Dashboard options 3B and 3C group visible cards from their actual data configuration and presentation compatibility. Business nouns in titles, stage labels, and card counts must not define group membership.

## Evidence

`dashboard.get_structure` returns a bounded `semanticProfile` for each visible data card. The profile contains only stable relationship evidence already present in the card configuration: dataset identity, dimensions, metrics and aggregation, filters, grouping, time grain, and drill fields. Missing configuration stays missing; it is never inferred from the title.

The Host compares profiles without a business-dimension whitelist. Shared dataset and compatible analytical grain establish a candidate relationship. Shared dimensions, metrics, filters, group fields, time grain, and drill paths strengthen or distinguish that relationship. Card type describes presentation compatibility but never fixes a card to a particular row or column.

## Planning

Cards with sufficient structural evidence are grouped deterministically. There is no numeric card-count or group-count limit. Cards with absent or conflicting evidence are the only cards sent to the existing single AI ambiguity pass. The AI receives compact profiles and existing deterministic anchors, returns structured JSON once, and is never asked to reconsider an already classified card.

Titles are used only after membership is known. A short group title combines reading stage with a grounded content summary. The summary may be generated by the existing bounded title call, but it cannot change membership.

Group membership planning does not change the existing compact-layout algorithm. Before invoking it, the Host may reorder members inside a group from data relationships and card-type compatibility so strongly related or visually complementary cards stay consecutive, while preserving the selected 3B/3C stage direction. The compact planner receives that final order and remains unchanged; the outer frame adopts its content height. No new candidate generation, scoring, sizing, or placement rule is added to the compact planner.

## Performance And Failure Behavior

The profile travels in the existing structure read, so the planner adds no frontend round trip. Payload size remains bounded and secrets are excluded. Diagnostics report deterministic, ambiguous, and AI-fallback counts and timing. Invalid or unavailable profiles degrade to the one-pass ambiguity path; they do not trigger retries or title-based guessing.

## Verification

Tests cover different titles with related configuration, identical titles with unrelated configuration, previously unseen business dimensions, missing profiles, card-type compatibility, bounded structure payloads, and no repeated AI call. Existing flat-group color and compact-layout tests remain independent.
