# 业务顺序与自定义美化

仅调整顺序或特殊样式时读取；配色和紧凑走 SKILL.md 预置短路径。

## 调整顺序

A/B/C 三种策略互斥，一次只采用一种：

- A 核心指标放顶部：指标卡即核心指标。把指标卡稳定移动到当前范围顶部；指标卡之间保持原相对顺序，非指标卡之间也保持原相对顺序。
- B 先总览再明细：先按内容关联形成语义关联集合，同一集合的卡片必须连续排列；B 在每个集合内按总览到明细排序。
- C 按现象到原因排列：先按内容关联形成语义关联集合，同一集合的卡片必须连续排列；C 在每个集合内按现象到原因排序。没有因果证据不声称原因已证实。

选择 3A/3B/3C 即授权全量重新编排，无需追问是否创建分组，无需等待“是/否”回答。用户明确要求“只排序、不分组”时才保留现有容器并执行普通排序。

为避免主代理反复分类，完整结构返回后立即调用一次 `davinci_planner.plan_semantic_grouping`，只传所选 `strategy`。Host 从真实回执提取可见有效卡片，忽略 Tab 内部成员、空文本实现卡片和隐藏占位节点；规则处理明显卡片，仅疑难卡片进入一次 AI 判断。规划器单次返回完整 `layoutArguments`，主代理不再重新分类，原样调用 `dashboard.set_widget_layout`，由既有 Host 紧凑布局链路执行。走 `preset` 路径时必须完全省略根层 `items`，不得发送 `items:[]`。

业务排序采用混合规划：Host 用随结构返回的精简数据配置指纹和实际 chartType 处理高置信卡片，AI 只判断剩余疑难卡片。B/C 综合数据集、指标、维度、聚合、筛选口径、时间粒度、分组和钻取关系判断关联；标题只用于阶段和组名，不决定成员。仍无法可靠关联的卡片保持原相对顺序。选项确定后直接进入有界决策，不为分析过程追加等待提示。

1. 使用 `dashboard.get_structure` 读取完整结构；有 nextCursor 时继续分页，取得全部根及子组件 ID、标题、实际 chartType、容器归属、精简数据配置指纹和同一 resourceRevision，包含隐藏 Tab 页和嵌套子项。指纹已携带决定相关性所需的数据集、字段角色、筛选、粒度与钻取证据，不额外逐卡读取配置。
2. 选择 3A/3B/3C 即授权全量重新编排：拆除全部已有原生平铺布局，释放出的子卡与当前根卡片一起生成完整 `orderedWidgetIds` 并重新分组。Tab 容器及其成员归属保持不变，其完整直接子项顺序继续通过 `scopeOrders:[{layoutWidgetId,orderedWidgetIds}]` 提交。
3. A 直接做稳定分区。B/C 先形成语义关联集合，再保持集合连续并执行集合内顺序；同一指标、时间范围与筛选口径是强关联证据，优先让数量/金额图与结构占比图相邻。语义配对优先于桶内原相对顺序，用户明确顺序优先。无数据卡仍保留 ID、数据和配置，不得仅凭无数据把卡片排到末尾。
4. 排序功能只负责确定顺序和可选分组。决策完成后进入下述紧凑与事务流程；模型不计算坐标，不查询业务数据来决定删卡，也不修改数据、筛选、图表类型、数值格式、单位或精度。

### 快速决策硬规则

1. 每张卡只生成一次 `topicKey` 和 `stageRank`，不得写多轮自然语言分析。`topicKey` 从精简数据配置指纹的真实关系得出，不维护业务维度白名单，也不维护业务对象白名单；标题只映射阅读阶段和生成组名。
2. 先按数据配置相关性与卡片类型形成关联集合，组内保持所选 3B/3C 的阶段方向；同阶段允许依据数据关系和卡片类型兼容性灵活调整顺序，使强相关或适合相邻展示的卡片连续，不固定排行榜或其他卡片的位置。相同数据关系且展示可行时允许跨阶段成组，展示可行性只影响是否创建容器，不改变数据相关性。组间按最小 `stageRank`、再按该组首张卡原始位置稳定排序；配置证据已确定的成员不得重新分类，也不得交给模型重新分类或比较标题候选。
3. 可靠关联集合直接建组，不设置卡片数量上限，也不设分组数量上限，不按固定张数机械拆组。证据不足的卡片不凭标题猜测，只进入一次带配置指纹和确定性锚点的 AI 判断。
4. B 固定映射总览、趋势、拆解/排行、明细；C 固定映射现象/结果、趋势、结构拆解、原因/归因、明细。仅执行一次集合校验：检查总数、唯一性、全集相等和组内连续性；通过后立即调用工具，失败时只做机械去重/补漏，不重新判断语义。
5. **硬停止：**不得在调用工具前逐张复述完整卡片清单，不得展示候选方案、自我反驳或出现“重新考虑/重新组织/再检查”；生成 `orderedWidgetIds` 和 `groups` 后不得重新推演。`comparisonPairs` 仅在出现明显且兼容的配对时生成，否则立即省略。

## 可选平铺分组与紧凑事务

选择 3A/3B/3C 后默认重建原生平铺分组，无需追问是否创建分组，无需等待“是/否”回答，也不得再次询问保留旧平铺还是全部重新分组。只有用户明确要求“只排序、不分组”时才保留现有容器并执行普通排序。

- 拆除全部已有原生平铺布局，释放出的子卡与当前根卡片一起进入同一轮关联判断；无需再次确认旧平铺移除清单或精确分组提案。Tab 容器及其成员归属保持不变，不拆除、不迁移其内部卡片。
- 每个新平铺分组至少包含 2 张卡片，成员必须来自同一可靠关联集合并在最终顺序中连续。不创建 Tab，不创建单卡分组，也不用 add/delete/copy/set_widget_container 逐卡重建。
- `regroup.containerWidgetIds` 必须列出全部已有原生平铺 Widget ID，不得包含 Tab Widget ID；旧平铺移除、子卡提升、新平铺创建和紧凑布局在一个原子事务内完成。
- B/C 先建立关联集合，再把合格集合创建为平铺分组，分别执行 B 的总览到明细或 C 的现象到原因顺序。A 在卡片存在可靠关联时遵守相同分组规则。
- 关联性不足时不创建分组，保留相关卡片原归属与原相对顺序，继续完成其余可执行排序，并在最终结果中说明未分组原因。

新平铺所在根画布只允许两种整行形式：单个平铺独占 24 列；只有连续两个“组内少于 3 张卡片且全部为指标卡或排行榜”的窄卡分组，才尝试两个平铺同行各占 12 列。若任一半宽组无法满足最小尺寸、排行榜纵横比，或两组紧凑后的高度不同，则两组都升级为各自 24 列独占一行。不允许 3 个及以上平铺共享一行，未分组根卡也不得与新平铺共享该行。先固定 24/12 外框，再在每个真实外框宽度内原样调用一次功能 2 紧凑布局，直接采用其子卡几何和容器内容高度；不得枚举其他外框宽度、跨组搜索或缩放紧凑结果。该规则只决定 12/24 外框选择，不限制语义分组本身的成员数量，也不按固定张数拆分分组。

新平铺容器背景由工具综合画布默认背景色和全部可见子卡的实际背景色，从白色及浅蓝、浅绿、浅黄、浅紫等低饱和浅底中选择与所有子卡差异足够大的一项；候选色只要与任一子卡过近就排除，禁止灰色或近灰色，并以不透明容器底色随事务保存。只有所有外框候选色都冲突时，才允许改动发生冲突的指标卡浅色背景后重新选择外框；普通图表、表格、排行榜及旧容器配色保持不变，不向 groups 虚构颜色参数。

关联明确的同行配对可使用 `groups[].comparisonPairs`，例如 `[["amount","amount-share"],["orders","orders-share"]]`。每对仅两个非指标卡 ID，必须属于同一组并按相同顺序相邻，各对不能共享成员。没有明确配对就省略，不按奇偶位置机械成对。工具在可读尺寸和锁允许时保持同行；不能同行时报告 `LAYOUT_COMPARISON_STACKED`，不突破尺寸锁或减少成员。

顺序及可选分组先应用到内存工作副本，再对根画布和每个平铺布局范围复用功能 2 的紧凑布局，并且原样调用既有算法；分组只提供成员与顺序，不得修改其候选生成、评分、尺寸策略或排布规则，平铺外框高度采用既有算法返回的内容高度。Tab 页面保持原归属，并使用同一紧凑能力处理其页面范围。全部范围成功后一次原子保存，任一范围失败则不保存任何修改。不得新增、复制或改写另一套紧凑布局算法，不得先保存排序或建组再另存紧凑结果。

3A/3B/3C 提交拆除旧平铺后的完整根 `orderedWidgetIds`、保留 Tab 的完整 `scopeOrders`、`groups:[{title,widgetIds}]`、`groupingConfirmed:true` 和 `regroup:{containerWidgetIds:[全部已有原生平铺Widget ID],confirmed:true}`。工具校验 ID 完整、唯一、移除范围、分组至少两张、集合连续、紧凑结果和 expectedResourceRevision 后一次写入。核对 `summary.requestedOrderApplied`、`summary.orderedScopeWidgetIds`、`data.grouping.groups`、`removedContainerWidgetIds` 与 `persisted`；预览不等于保存，版本冲突须重新读取并重新判断，不能拿新版本号重放旧计划。

角色和关联只判断一次，ID 序列只生成一次。失败后不另调普通 reorder、compact 或逐卡操作掩盖失败，不排除成员后重试。完成后说明采用的策略、处理范围和实际创建的分组；没有建组时说明用户选择了只调整顺序，还是关联证据不足。

此行回退仅适用于普通 compact/reorder 的自动 content 最终根行，align 保留原列。先走现有混排，先尝试用有业务用途且兼容的其他卡片填补空白，保持阅读顺序和分组边界；只有没有合适的其他卡片可填补时，孤立行中至少 2 张自动指标卡才按 24 列整数栅格分配整行可用宽度：可整除时等宽，不可整除时近等分、最多相差 1 格（例如 5 张可为 5、5、5、5、4 格，不用 4.8 格）。同行等高，取实际分配宽度下有限探测中实测可容纳全部内容的最小共同高度，不得超过原紧凑行最大高度；不承诺全局最小高度，界内没有可行候选则保留紧凑行，不额外增高。须实测分配宽度和共同高度，保留卡间间距及内边距。单指标保持紧凑，回退不改动单指标及显式尺寸；preserve 和显式尺寸锁优先，排行榜保持窄而高，ID、数据和非布局配置不变。此根行回退在同次布局调用内完成，不新增参数或模型手算坐标，不跨组或突破受保护范围；无法实测内容适配或与锁冲突时保留约束并如实说明。

获批分组的临时根尺寸预览（capturePlan）禁用此回退，同时关闭根级宽度/高度填空（width/height gapfill）与指标行扩展（metricrowjustify）；capturePlan 不先扩展根行尺寸，根级填空尺寸不传入 group，避免先在根层扩卡后再使分组二次膨胀。group 使用内容尺寸与内部实时实测，这不表示禁用获批新组的内部候选规划；capturePlan 是内部路径，不是工具参数。

未获批移除的既有分组仍受保护：不改变其容器尺寸、成员归属或内部子卡几何，隐藏 Tab 页也不例外。调整顺序不移除既有容器，不把新组内部优化权限扩展到其他既有组。

获批新组内部遵循相同业务区域原则：在获批成员与顺序内优先用有业务用途且兼容的卡片填补空白，协调同行尺寸、区块边界和间距，不为填空混入无关卡片或压扁排行榜。工具进行多宽度与指标卡尺寸候选联合比较，并在保存前对最终候选执行精确内部 DOM 验证，而非仅将原根卡紧凑尺寸换算为内部栅格。同行协调须以实际候选及验证证据为准，不能仅凭单卡测量或已生成候选宣称协调完成。显式 preserve 和尺寸锁优先，ID、数据和非布局配置不变；模型不算内部坐标、不新增工具参数。分组候选缺少必要测量或最终验证证据时不写入，如实报告限制，不自动删减成员重试。

按业务语义划分业务区域，使相关卡片相邻并遵循用户选定的阅读顺序；组名、成员和区域数量取决于当前内容，不套用固定组数、固定卡片数量或个别看板案例。区域边界、对齐、间距和信息层级是通用目标，不为填空把无关内容并入同组或跨越获批边界。工具负责实际测量与布局，不把语义提案当作已经创建容器或完成内部优化的证据。

剩余空位是质量提示；不得通过裁切内容或越过尺寸锁填满。没有实际渲染验证不宣称分组视觉验收已通过。

## 自定义配色

白底采用白卡、深色文字和蓝色重点；彩色背景采用浅蓝、浅青、浅紫。保留已有告警、涨跌语义色。预置映射由工具执行，不按 ID 反复分组。

自定义颜色或局部字段才读目标 appearance / metric 能力。只写明确支持且可写的字段，不从一张卡推断其他卡的能力，不修改数值格式、单位、精度或数据配置。

## 空间与完成边界

紧凑同时处理卡内无用途空间和外部空隙，并尽量对齐。字体、标题、图例、轴标签、比较值、表头和分页都属于内容。低柱、零值、稀疏散点和目标线以上的量程空间不是尺寸冗余。

布局范围以用户可见结构为准。只有当前可见且能解析到有效根画布、平铺或 Tab 作用域的节点才是布局卡片。Tab 未激活页、系统占位节点与父容器已失效的隐藏残留节点一律退出求解和验收，保持原样且不阻断其他作用域。不将这些内部节点包装成用户可见卡片，不要求用户寻找、删除、改色或重新归类。

不能通过删图、隐藏内容、改变数据行数、类型、筛选、格式、单位、精度、阈值或坐标范围制造紧凑。所有非容器卡的 ID、数据和非布局配置保持不变。嵌套组件不属于根画布坐标系；调整顺序始终保护既有容器和子项，不提升或迁移其成员。

排行榜属于细长卡片，不属于普通宽图表。排序、紧凑、配色后的布局基线都必须检查排行榜形态；出现宽扁排行榜时不能按已完成返回。只有为消除不可避免的行尾空白时，工具才可把排行榜有限扩宽，仍必须保持高卡形态。

只根据回执报告实际保存变更和限制，没有发布请求不发布。零变更不等于布局最优：`unchanged`、`layoutChangeCount:0`、`persisted:false` 或顺序未变只表明本次没有相应变更，不能宣称“已是最优”“没有优化空间”或“无需再优化”。未知写入结果先核查，不重复整个批次。配置校验不能替代视觉验证，不能凭常量断言全部卡片已达内容最小尺寸。
