# 紧凑与一键整理短路径

紧凑布局直接调用一次：

```json
{"preset":{"mode":"compact","sizing":"content"}}
```

一键整理仪表盘直接调用一次：

```json
{"preset":{"mode":"organize","sizing":"content"}}
```

不先读结构、列 ID 或计算坐标。业务排序才按 beautification.md 取得语义，并在同一次 reorder 调用中完成布局。最多 200 个根组件；保留现有子组件，成功最多保存一次，不发布。

## 工具行为与限制

- 当前主路径统一由 `dashboard.set_widget_layout` 进入既有 Host 紧凑布局链路，不走旧前端排版路径。链路比较完整行与跨行混排候选，保留阅读顺序，允许多小卡与大图并排。最终几何调整后再比较候选；不人为插入空隙来规避连通空洞检查。
- 一键整理仪表盘是受控整理模式：优先对齐和减少可避免留白，不追求全局最优。工具限制候选规模并保留可用保底布局；搜索预算耗尽时也优先返回当前合法方案，不要求模型换模式或手算坐标。
- 此行回退仅适用于普通 compact/reorder 的自动 content 最终根行，align 保留原列。先走现有混排，先尝试用有业务用途且兼容的其他卡片填补空白，保持阅读顺序和分组边界；只有没有合适的其他卡片可填补时，孤立行中至少 2 张自动指标卡才按 24 列整数栅格分配整行可用宽度：可整除时等宽，不可整除时近等分、最多相差 1 格（例如 5 张可为 5、5、5、5、4 格，不用 4.8 格）。同行等高，取实际分配宽度下有限探测中实测可容纳全部内容的最小共同高度，不得超过原紧凑行最大高度；不承诺全局最小高度，界内没有可行候选则保留紧凑行，不额外增高。须实测分配宽度和共同高度，保留卡间间距及内边距。单指标保持紧凑，回退不改动单指标及显式尺寸；preserve 和显式尺寸锁优先，排行榜保持窄而高，ID、数据和非布局配置不变。此根行回退在同次布局调用内完成，不新增参数或模型手算坐标，不跨组或突破受保护范围；无法实测内容适配或与锁冲突时保留约束并如实说明。
- 获批分组的临时根尺寸预览（capturePlan）禁用此回退，同时关闭根级宽度/高度填空（width/height gapfill）与指标行扩展（metricrowjustify）；capturePlan 不先扩展根行尺寸，根级填空尺寸不传入 group，避免先在根层扩卡后再使分组二次膨胀。group 使用内容尺寸与内部实时实测，这不表示禁用获批新组的内部候选规划；capturePlan 是内部路径，不是工具参数。
- 未获批移除的既有分组仍受保护：不改变其容器尺寸、成员归属或内部子卡几何，隐藏 Tab 页也不例外。获批完整重组只处理精确移除清单和成员提案中的范围，不把新组内部优化权限扩展到其他既有组。
- 获批新组内部遵循相同业务区域原则：在获批成员与顺序内优先用有业务用途且兼容的卡片填补空白，协调同行尺寸、区块边界和间距，不为填空混入无关卡片或压扁排行榜。工具进行多宽度与指标卡尺寸候选联合比较，并在保存前对最终候选执行精确内部 DOM 验证，而非仅将原根卡紧凑尺寸换算为内部栅格。同行协调须以实际候选及验证证据为准，不能仅凭单卡测量或已生成候选宣称协调完成。显式 preserve 和尺寸锁优先，ID、数据和非布局配置不变；模型不算内部坐标、不新增工具参数。分组候选缺少必要测量或最终验证证据时不写入，如实报告限制，不自动删减成员重试。
- 指标尺寸必须有本次内容测量依据；不可测内容保留并通过 issues 报告。尺寸锁或内容适配约束使回退不可行时，保留约束并报告限制；不能声称已达到紧凑极限。
- 排行榜自动宽度保持窄列，高度根据实际像素比例确定，不能仅凭 8×12 栅格判断细高。普通图表可在原有高度范围内保留部分高度以填补相邻空位；多指标行仅按上述条件回退。
- 表格保持单表，透视表同样保持单表；自动 content 允许横向扩展，其最窄宽度依据整屏可用宽度的一半与当前容器可用宽度，取两者较小值，并由工具按实际像素换算本层整数栅格。容器本身不超过半屏时，表格占满该容器，不能再缩成容器的一半。保持当前高度，在可用空间与既有布局约束内利用横向空位；显式 width 锁与 preserve 优先，其中 `sizing:"preserve"` 保留原尺寸。不拆表、不减少数据行数，不改变数据和非布局配置。是否实际扩宽以本次回执为准，尺寸策略不等于表头、内容或滚动区域已经通过渲染验收。
- 已有平铺及 Tab 保留归属、子组件几何和不可测内容。检查根容器高度，不宣称组内空洞或隐藏页已优化。Tab 的限制不影响其他根组件收紧。
- 明确尺寸和顺序是硬约束。align 保持原 x 列；preserve 保留大小；content 使用内容尺寸；auto 在一次工具内先保留尺寸，基线失败时再按内容处理。不得由模型换模式重试。
- 保存前检查完整 ID、合法边界、重叠、阅读顺序和容器高度。根层空洞与排行榜比例保留为质量提示，不否决合法布局；9 格只是统计阈值，不是保存门槛。自动尺寸仍以细高排行榜和紧凑指标为目标，明确尺寸锁优先。可用布局不代表视觉达标，也不证明全局最优。

## 回执

`constraints.solverFinal:true` 是兼容字段，表示本次布局调用已结束，不代表执行了 Host 求解器。直接报告回执，不补调布局、不读原坐标猜未保存候选的失败原因、不手算尺寸。不得仅因存在空洞建议删除容器、切换 combo 或更改业务顺序。

核对 status、persisted、preview、requestedOrderApplied、summary.contentFit 和 issues。status:success 且 persisted:true 时报告布局已保存，附带空白或保留项；不能把 LAYOUT_REMAINING_SPACE、hasLargeEmptyRegion:true 或形态提示称为失败。无需改动的 persisted:false 和预览不冒充保存。不因质量提示追问是否重排、换模式或删除容器。真实权限、版本和保存错误必须如实报告。

一次成功保存、几何回放或 candidateSearchConverged 都不是视觉验收。没有真实前后渲染和完整耗时，不承诺达到好样例或 30 秒端到端目标。发出写请求但未确认时报告结果未知，不能自称回滚。

只在用户要求预览时传 dryRun:true。用户再次明确要求继续紧凑是新请求，与失败后模型自动重试不同。
