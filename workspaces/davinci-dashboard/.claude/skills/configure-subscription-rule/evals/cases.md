# 订阅配置验收

[共享用例](cases.json) 记录用户需求、九入口归属、代表性 operation 和预期副作用。它是验收输入，不是已完成测试的证明；每次报告实际执行的套件、数量及未运行原因。

## 全领域

- 九入口：三个订阅中心及个人/空间/同步仪表盘的推送、预警；六个仪表盘位置均个人，两个空间订阅中心归空间。包含普通空间成员、代查和快照门禁。
- 空白与模板起稿、原生快捷草稿接续；模板锁、个人接收人、手动修改和 revision 共用同一原生 Store。
- 七步：全部执行时间类型、多查询/同源不同查询、日期与参数、同环比输出、OR-of-AND 条件、命中上限200/1–1000、逐条/逐组/全部、附带查询映射、固定/群组/动态员工、七类有序内容与变量、名称和标签。
- 修改一个时间或标题时其他步骤不变；删除查询暴露具体下游失效引用；空候选区分当前范围与全域；不同父级候选不互相撤销。
- 配置请求 → 可编辑未保存设置；finish 连续校验后交接用户发送预览并手动保存；Agent 不执行 create，已有规则不误当新配置保存。
- 人机交替：配置后只切七步不改变有效版本；人工改时间后 Agent 改标题保留人工时间；Agent 执行期间人工修改不能被旧补丁覆盖。
- 保存入口仅为原生页面按钮，保留提交锁和结果未知保护。Agent 隐藏保存工具且直接调用也拒绝；人工保存后只报告实际状态。
- 操作结果：新写入后被发送方式裁掉必须报错并原子回滚；requiresTimeFilter 在指标搜索时可见；截断候选不当成全集。

## 验证层次

1. 正式契约用 JSON Schema 检查真实参数边界及回执结构；不能只断言工具名称存在。
2. 原生 Jest 测试操作结果、store revision、实际保存参数、上下文/权限/候选；前后端 adapter round-trip 检查字段/比较身份不丢失。
3. 现有 model simulator 只验证模型协议与代表性目标，不替代后端或浏览器。所有配置请求均交接原生页面预览/保存；finish 回执匹配当前 revision 才能结束。
4. UAT 用真实页面检查配置可见与可编辑、最终步骤定位、手动预览/保存、最终归属及实际启停状态。没有实际执行就列为待验收，不用静态测试冒充整链路通过。

## 性能

默认 get_context 不查规则列表，review 不执行数据查询；复用现有草稿/refs，以1–32项原子批次提交，按依赖读取候选。start/apply 共用完整配置能力；原生组件预警不另搜全局同名数据；添加同环比保留原值引用。测试这些可确定的调用次数，而不以开发机耗时承诺在线响应。

UAT 同一组请求记录首个有用响应、可编辑草稿完成时间、工具调用数、澄清次数、数据查询次数，按个人/空间/预警分别统计 p50/p95。用户澄清、手动预览和保存的时间单独统计。未跑真实模型和UAT时，p50/p95为待测，不填估算值。

## 本轮原生工具验收

cases.json 的 nativeExamples 为五条完整参数路径，与 references/examples.md 同源生成并通过正式输入契约检查：纯通知、截图/AI/跳转、昨日四列表格、原值与日环比、异常订单动态接收人。短引用仅为占位，实际浏览器测试使用真实 Controller 生成的引用。

关键回归：旧统一入口不再曝光；get_context只读；components与旧快捷参数不混合；同源多查询保留；all不要求queryRef；no-op不要求revision增长；必填标题首次自动补齐；人工清空/手改不覆盖；旧冻结Skill明确升级；真实SDK回执和正文进度恢复；finish ready后模型一次业务核对。schema通过不等于真实模型或生产数据验收通过。
