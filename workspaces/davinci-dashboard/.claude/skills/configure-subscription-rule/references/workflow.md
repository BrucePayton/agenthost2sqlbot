# 按依赖推进订阅配置

## 共同起点

每种场景先在正文回显需求，识别归属、时间、来源、判断/卡片粒度、接收人和内容。复用当前可信上下文；指定空间且当前无 space.list 时先 ui.open_space_page，再 space.list → space.open(destination=subscription)，再 get_context。来源属于哪个空间与规则归属分别核实，不能默认把指定空间规则做成个人规则。

模型直接选择原生业务工具及参数；工具负责本次动作的合法性、精确绑定、原子执行和回读；Host 负责传输、真实回执、事实恢复及正文进度。原生 Store 是唯一可写配置。检查点保存原需求、补答、确认引用和当前回读，不保存待执行业务计划。

理解依赖后，证据已齐的配置合并一次 start/apply；引用已齐就一次配置并 finish。仍有候选查找或真实澄清时，独立确定项可先提交，不为展示进度额外拆批。已有本次草稿接续，模板/指标预警继承原生种子；无关草稿先解释对象冲突。已声明新建并无冲突时，首次创建工具自动补齐尚缺的标题/名称，不占额外模型往返。

## 四条业务路径

| 路径 | 资源定位 | 执行 |
| --- | --- | --- |
| 固定内容通知 | 指定空间、成员/群、已有图片 | 回显 → 核实归属 → 时间与 scheduled_no_dataset → 固定收件人及有序内容 → finish |
| 仪表盘内容订阅 | 指定仪表盘及其真实内容组件 | 回显 → 核实归属 → 时间与 scheduled_no_dataset → 内容资源 → 接收人与内容 → finish |
| 定时数据推送 | 指定来源优先，集中核验全部字段用途 | 回显 → 核实归属 → 时间与 scheduled_dataset → 查询 → 卡片/映射/接收人/内容 → finish |
| 条件预警 | 指标种子或指定数据集，补齐判断及分发依赖 | 回显 → 核实归属 → 时间与 conditional → 查询 → 条件/卡片/映射/接收人/内容 → finish |

箭头表示依赖，不表示每步各调一次模型。同批确定项合并 operations；有真实歧义就问，独立项可以先配置。工具检查不过时定向修正，不重新从第一步规划。

纯通知保留用户文字、月份、链接、顺序和格式。@所有人用 mention-all；它不等于给全体空间成员逐人发送。新图片需用户在编辑器上传；不编造 imageRef。

仪表盘内容支持富文本、数据表、截图、图表、图片、按钮、按钮组及其变量/下载组合。截图不需要另建数据查询；若明确包含数据表或数据变量，再补该部分查询。截图、AI与跳转复用同一父仪表盘；AI 用真实 contentKind=ai_interpret 的 widget，不能生成静态文字冒充，也不能仅凭组件名称认定其类型。

数据路径同时考虑时间、指标、条件、分组、动态员工、正文、下载字段。先指定来源再定向查字段；已确认来源不重新模糊搜索。原生 field 查询可用 | 合并关键词；截断时按 nextOffset 补所需页，不把过滤结果当全表。通用目录证据齐备就 bind_dataset_query 精确绑定，原生候选则 upsert_dataset_query，不做两轮等价搜索。不要把每个字段拆为一次推理。

指标卡预警从 alert_widget 定位并导入原生配置；widget 是内容目录，缺内容组件不证明预警指标不存在。在当前仪表盘快捷入口用实际已开的配置。可以先建未绑定预警填写时间，再 import_widget_source 导入同一任务，保留独立项。原生已有日期/原值/比较输出先复用；用户要求昨日时核对真实时间字段，filtersComplete=true 时用 filterEdits 将对应日期改为滚动昨日，保留其他筛选和参数；不因 metadataReady=false 重查已有全部字段。所需比较确实缺少时 merge 添加，读取不全才补读。

## 粒度、混合与续改

all/record/group、多查询和混合内容是组合维度，不新增流程。按业务订单发送不等于按商品物理行发送；先确认订单粒度及金额口径。异常记录、每张卡片、动态接收人、正文和下载须范围一致，不能因一条异常给所有负责人发全部数据。

同源多查询保留各自 queryRef、时间、筛选、参数和输出；不按数据集去重。附带查询关联用真实字段映射。员工字段必须具备原生账号资格并加入对应查询维度，避免仅按姓名或 varchar 推断；不得用固定本人替换动态接收人。

用户补答保留原需求和已选引用；用户纠正只改受影响项。日期变化检查比较/标题，粒度变化检查映射/内容。以最新回读和 revision 保留手动修改；发生冲突重读后只提交本次差异，不重放历史计划。字段候选与查询输出引用分别使用。

## 正文与页面联动

Host 根据实际工具及 operations 生成正文进度，原生工具将页面定位到本次配置对应步骤；模型无需补 presentation 或重复同一开始/完成消息。模型仅补需求回显、业务澄清或回执未覆盖的说明。

关联配置成批提交，不为刷新七个页面拆成七轮。页面切换不是完成证据；用户手动切页、SECTION_BUSY 或 navigation=user_controlled 时尊重其选择。

## 完成与交接

最后一批 finish=true，工具调用原生静态检查，返回当前 configuration、queries、completion。没有本次写入时 review_draft(finish=true)。ready 证明当前版本结构检查通过，不证明用户业务要求已全部落实；模型用原需求和补答对照实际回读一次。缺项就局部补齐，全部符合就结束，不重复查找、查数或无意义 review。

最终正文总结真实名称、时间、来源/日期/口径/筛选/比较、条件、卡片范围、接收人、标题变量及内容。面向用户写业务名称，不罗列内部引用。明确“尚未保存，实际数据待预览验证”，提示：

> 请在“命名并保存”页面右下角点击“发送预览”，检查实际数据和消息展示效果。确认符合预期后，再保存；需要调整也可以继续告诉我。

navigation=followed 才说已经到该页；用户手动切页则请其打开。Agent 不调用数据预览、发送预览、试发、保存、启用或发送。
