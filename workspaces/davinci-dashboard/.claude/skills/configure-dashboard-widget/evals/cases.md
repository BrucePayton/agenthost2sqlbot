# P0 回归用例

## 用例 1：新建完整柱状图

用户：`在当前仪表盘增加各城市奢侈品门店成交订单金额柱状图，最近30天，按金额倒序。`

背景：用户已指名完整指标名「奢侈品门店成交订单金额」，目录里只有一个数据集（662）的字段精确匹配这个全名，不构成歧义，不应触发二选一提问。

期望：读取页面 → 解析/检索 dataset 与 3 个字段 → 权限校验 → 一次 `dashboard.apply_widget_spec(create=...)` → 一次读回，全程不提问。不得创建空 Widget，不得打开市场要求用户手工绑定。

## 用例 2：已有指标卡完整配置

用户：`把 widget 10814 配成近30天 O2O 奢侈品成交额。`

背景：用户已指名完整指标名「O2O 奢侈品成交额」（含渠道限定词），目录里只有一个数据集的字段精确匹配这个全名，不构成歧义，不应触发二选一提问。

期望：定位指标与时间字段 → 权限校验 → 一次 `dashboard.apply_widget_spec(widgetId=10814)` → 读回，全程不提问。不得把 10814 当 dashboardId。

## 用例 3：口径歧义

用户：`创建一个新的目录叫奢侈品，创建一个功能页叫奢侈品回收看板，然后创建一个奢侈品最近7天成交额的指标卡。`

背景：「奢侈品成交额」没有渠道/门店限定，目录同时命中 O2O 与门店两种实质不同口径；目录和功能页名称本身没有歧义。

期望：先用小批元数据定位指标；最多补一次缺少的比较证据，给出数据集、指标和真实定义后提问。选择提出前不创建目录或空功能页，不试配、不查数。用户确认后再创建并配置；已有成功操作沿用，不重建目录或看板。用户明确要求先建目录时才先完成独立部分。

## 判失败

- 同 revision 下相同工具和参数重复 3 次或以上。
- 写操作之后没有读回。
- 只完成创建、重命名、导航或打开面板便宣称完成。
- 因预加载数据集选项为空而要求用户手工添加一个已授权数据集。
- 工具最终产出留有空 Widget 或未配置必填字段。


## 用例 4：只有近似候选的看板任务

用户：`再建一个3c看版，增加3c最近7天回收额指标卡和日同环比。`

背景：当前协同空间、分组和创建权限明确；检索只找到「门店预估销售额」，没有工具证据证明它等同于「3C回收额」。

期望：说明本次只找到近似指标、没有等价证据，请用户提供业务范围或已有看板线索；不先创建空看板，不读取无关旧卡片，也不把预估销售额命名为回收额。已知且本次需要的比较条件合并询问，各选项保持单一编号体系。用户只回复比较选项「2」不等于确认指标口径。冲突回复只澄清冲突，已有完成操作不重做。

## 用例 5：按战区拆分趋势线

用户：`增加近30天各战区回收成交额趋势图。`

背景：数据集、成交额指标、日期和战区字段均已唯一验证。写入回执 persisted:true，
dimensions 含日期和战区，probe.rowCount:376，但 appliedSpec.group:null。

期望：输入为一个指标、dimensions 按日期/战区排序；识别分组未生效，最多读回一次核对
group。若仍为 null 或字段不匹配，报告工具回执与预期不一致；不能因 376 行含多个战区就
宣称已生成多条线，也不能自动改口径或反复写入。若回执 group.enabled:true 且 fieldId
匹配战区，才可确认已配置战区系列；单维度请求读回不得残留旧战区分组。
